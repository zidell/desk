# desk 검증 상태

OS별로 실제로 확인한 환경과 결과, 아직 확인하지 않은 조건을 적는다. 코드가 있다는 것과 실제로 검증했다는 것을 구분한다.
변경할 때마다 해당 OS 절을 고치고, 확인 수준을 **직접 실행**, **빌드만**, **문법 검사만**, **코드만**으로 적는다. 이력은 git 커밋에 남긴다.

## 재검증이 필요한 변경

| 변경 | macOS | Windows | Linux |
|---|---|---|---|
| 이동 중 픽셀 비교 제거, 클릭 영역 픽셀은 이동 전 한 번만 비교(호버 변화 무시) | 직접 실행(웹 표 "수정" 링크) | 코드만 — 재빌드·검증 필요 | 문법 검사만 |
| 비밀값 가리기(글자·그림) | 직접 실행(가짜 값 페이지로 `see`·`shot`) | 문법 검사만 | 문법 검사만 |
| 첫 실행 권한 점검(`desk permissions`, `doctor` 안내) | 코드만 — Swift 빌드·실행 필요 | 문법 검사만 | 직접 실행(`doctor`) |

## macOS

- 확인한 것: 클릭 대상 유지(Chrome 웹 접근성의 노드 흔들림), 창 ID 기준 창 판정, ⌘ 고착 수정, `click X Y --force`, 비밀값 가리기.
- 자동 테스트가 없다. 변경 뒤 Swift 빌드와 실제 앱·웹 화면에서 직접 확인한다.

## Windows

환경: Windows x64, Python 3.13, NVIDIA RTX 5060 Ti 8GB, 메모리 약 32GB, 단일 2560×1440 화면.

| 검증 | 결과 |
|---|---|
| Framework64 `csc` 콜드 빌드, 설치된 `desk.exe`/`desk.cmd` | 성공. help·status·doctor 실행 |
| Unicode 인수 | 한글·공백·내부 따옴표·후행 역슬래시·특수문자·emoji 보존 |
| 종료 코드 | 1·3·5·6 보존 |
| 중지 상태 | stop 이후 say/key가 3, end도 중지 상태를 지우지 않음 |
| Windows OCR | ko recognizer로 한국어·영문·숫자와 화면 좌표 변환 |
| 인식 | UIA + OCR + GPU 검출 결합 목록과 번호 그림 |
| 창 전환 감지 | 다른 앱으로 바뀌면 입력하지 않고 6 |
| GPU·모델 | PyTorch 2.11.0+cu128 CUDA, named pipe로 검출기 재사용, 검출기+비전 서버 시작 약 6초 |
| `smoke.py --ui --widget` | 기본 5 · 실제 UI 6 · 위젯 1, 12개 통과 |
| `reflow.py` | 14개 통과: 리플로우·컨트롤 교체·캔버스 변경 시 클릭 0회, 다른 영역 로딩 허용, 오래된 근거 거부 |
| 실제 업무 | 쇼핑몰 사이트에서 한글 검색·검색 실행·상품 탭·PageDown/Ctrl+Home |

한계: 접근성 식별자가 없고 픽셀까지 같은 대체 대상은 구별할 수 없다. 화면 검사와 OS 입력 전달 사이의 시간 간격을 0으로 만들 수는 없다.

## Linux

환경: Ubuntu 26.04.1 LTS, KDE Wayland, KWin 6.6.6, Qt 6.10.2, Python 3.14, 2560×1440(140% 배율). X11은 Xephyr 1200×900과 최소 EWMH 창 관리자, 중지 컴포넌트는 별도 D-Bus 세션의 중첩 KWin.

| 검증 | 결과 |
|---|---|
| 공통 화면 근거 회귀(`smoke.py`) | 11개 통과: 원본 보존, 다른 창·영역 밖·입력 세대 거부, 대상 교체·캔버스 변경 거부, 분수 배율 캡처, 따옴표 든 Tesseract TSV, 잘못된 사각형, 패널 픽셀 |
| 실제 KDE Wayland UI(`smoke.py --ui`) | 17개 통과: OCR/AT-SPI, 버튼·체크박스, 팝업 메뉴, 한글 붙여넣기, 드래그 선택, 휠, Ctrl 조합, 도구 ESC, 리플로우 클릭 0회, 포커스 변경·화면 밖 좌표 거부, 영속 중지 |
| X11 UI | 17개 통과(오른쪽 클릭·팝업 메뉴·드래그·휠 포함) |
| KWin 안전 컴포넌트(`guard_smoke.py`) | 6개 통과: 5px 무시, 10px 감지, ESC 앱 전달 차단, 중지 후 입력 거부, heartbeat 만료 중지, 눌린 Shift 해제 |
| 접근성 작업 프로세스 재사용(`test_accessibility_worker.py`) | 6개 통과. 실제 AT-SPI 조회 20회에서 pidfd가 첫 조회에서만 늘고 이후 그대로 |
| 실제 업무 | Chrome에서 쇼핑몰 검색창 클릭, 한글 붙여넣기, 검색 결과 확인 |

한계: 시스템 AT-SPI 라이브러리의 최초 연결 핸들 누수 자체를 고친 것은 아니다(앱 전용 런타임으로 피한다). 아이콘 검출기와 로컬 비전은 연결하지 않았다.

## 아직 확인하지 않은 조건

- 물리 입력부터 전체 작업 종료까지의 중지 지연
- 다른 DPI 배율, 다중 모니터, 음수 원점, 실행 중 모니터 구성 변경(세 OS)
- 관리자 앱/UAC, 잠금 화면에서의 실제 거부와 사용자 인계
- Chrome·Electron·OS 설정·파일 선택창 각각의 전체 업무 흐름
- CUDA가 없는 Windows의 CPU 모델 실행
- GNOME·다른 Wayland compositor, 실제 KDE/GNOME X11 세션의 전체 업무
