# desk 검증 상태

OS별로 실제로 확인한 환경과 결과, 아직 확인하지 않은 조건을 적는다. 코드가 있다는 것과 실제로 검증했다는 것을 구분한다.
변경할 때마다 해당 OS 절을 고치고, 확인 수준을 **직접 실행**, **빌드만**, **문법 검사만**, **코드만**으로 적는다. 이력은 git 커밋에 남긴다.

## 픽셀 비교 허용 범위

- 2026-11-18 실제 Device Hub·Safari의 정지된 클릭 대상 캡처에서 한 채널 값이 1만 다른 사례를 확인했다. `widget.json`의 `clickPixelTolerance=3`으로 RGB 각 채널의 최대 차이를 제한한다. 모든 픽셀에 같은 상한을 적용하며 변경 픽셀 비율·평균 오차·위치 보정으로 큰 차이를 통과시키지 않는다. 창·대상 정체·좌표·사용자 입력 검사는 그대로다. 접근성 정보가 없는 대상에서 모든 채널 차이가 상한 이내인 변화는 구별하지 못한다.
- 공통 Python 초기 검사·캐럿 예외·이동 후 검사와 macOS Swift 초기 검사·캐럿 예외, Windows C# native step이 같은 설정을 사용한다. Linux는 공통 Python 비교 경로를 쓴다.
- 화면 입력 없이 실행하는 회귀: `python skills/desk/tests/test_click.py -v`(Pillow 필요). 미세한 채널 변화 허용, 한 픽셀의 상한 초과·1px 버튼 이동·글자 변경·크기 변경·대상 교체·다른 창·사용자 입력 거부를 확인한다. macOS에서는 실제 Swift 비교 함수를 컴파일·실행하는 검사도 포함한다.

## macOS

- 자동 패치: 공통 회귀 21개 통과. 임시 git 태그·worktree·사본 교체/복구·동시 실행·로컬 변경 보존·재시도·끄기·새 프로세스 실행을 확인했다. 실제 설치된 실행기와 Python 진입의 `update`, `doctor` 권한·링크, GitHub ZIP 검사, 격리 Claude 플러그인 CLI의 0.2.1→0.3.0 캐시·메타데이터 갱신도 확인했다. 화면 입력은 하지 않았다.
- 확인한 것: 클릭 대상 유지(Chrome 웹 접근성의 노드 흔들림), 창 ID 기준 창 판정, ⌘ 고착 수정, `click X Y --force`, 비밀값 가리기.
- 화면 입력 자동 테스트는 없다. 화면 제어 변경 뒤 Swift 빌드와 실제 앱·웹 화면에서 직접 확인한다.

## 아직 확인하지 않은 조건

- 물리 입력부터 전체 작업 종료까지의 중지 지연
- 다른 DPI 배율, 다중 모니터, 음수 원점, 실행 중 모니터 구성 변경(세 OS)
- 관리자 앱/UAC, 잠금 화면에서의 실제 거부와 사용자 인계
- Chrome·Electron·OS 설정·파일 선택창 각각의 전체 업무 흐름
- CUDA가 없는 Windows의 CPU 모델 실행
- GNOME·다른 Wayland compositor, 실제 KDE/GNOME X11 세션의 전체 업무
